# 样例（examples）

本项目的处理对象是 **《晶核》游戏官方更新公告**（真实语料）。本目录附带了 **2 份真实公告**经管线加工后的
**产物样例**，绕开了源 PDF（大体积/版权），以便一眼看清「结构感知」链路的数据形态。

> 源语料 `test/`（54 份 PDF，约 125.4MB）**不纳入版本控制**，仅本地运行用；复现方式见 README「快速开始」。

## 样例清单

每个公告对应三个产物，分别对应管线的不同阶段：

| 文件后缀 | 阶段 | 说明 |
|---|---|---|
| `*_extracted.md` | ① 数据准备（人工核对） | 管线从 PDF 提取并清洗后的**可读文本**，用于人工确认结构是否正确 |
| `*_blocks.jsonl` | ① 数据准备（中间表示） | **Block 语义中间表示** `{kind, text, ...}`，`kind ∈ {heading, para}` |
| `*_chunks.jsonl` | ③ 结构感知切片 | 切片产物 `{id, doc, section_path, text, rows, start_block, end_block}` |

选取的两份公告：
- `7月8日更新公告丨新职业「艾尔莎」上线 三周年庆典活动开启` —— 篇幅大、小节多，展示**标题栈 → `section_path`** 的层级。
- `8月19日更新公告丨PVP玩法平衡调整 艾尔莎转职限制解除` —— 篇幅较小、含并列子标题，展示小节切分。

## 数据形态速览

**Block（`*_blocks.jsonl`，以 `7月8日…` 为例：111 个块 = heading + para）**
```json
{"kind": "heading", "text": "三周年庆典活动"}
{"kind": "para", "text": "阿特兰世界与大家见面就快3周年啦……"}
```

**Chunk（`*_chunks.jsonl`，以 `7月8日…` 为例：44 个 chunk）**
```json
{"id": "chunk_000364",
 "doc": "7月8日更新公告丨新职业「艾尔莎」上线 三周年庆典活动开启",
 "section_path": ["7月8日更新公告丨新职业「艾尔莎」上线 三周年庆典活动开启"],
 "text": "7月8日更新公告丨新职业「艾尔莎」上线 三周年庆典活动开启\n亲爱的冒险者：……",
 "rows": [], "start_block": 1, "end_block": 4, "start_page": 1, "end_page": 1}
```

`section_path` 为**完整标题路径**（如 `[标题] > 三周年庆典活动`），命中后凭 `doc + section_path + start/end_block(+start/end_page)`
即可**回溯回原文 + 页码**，实现「附原文链接」。

## 局限（如实说明）

- 本公告语料的解析产物 **只有 `heading` / `para` 两种 Block，没有 `table`** —— 原因是**这些公告本身不含真表格**。
  注意：`page.find_tables()` 会**误报**（实测把「团战挑战规则调整」等**板块标题**误报成 1×1 的"表格"），
  已由 `_is_fake_table()`（**单行/单列 → 判为误判**）拦截；误报区域的短文本转成 `heading` 候选，故最终不产生 `table` 块。
- **历史误报修复**（已记录）：曾把 `find_tables()` 输出误当"真表格"写进结果（未人工核实，属**误报陈述**），
  后由 `_is_fake_table()` 修正，见 `docs/问题与处理记录.md`（附录·历史基线）与 `docs/数据准备方案.md`（2.4 节）。
- `table` 是管线的**通用能力**，但**本次公告语料无真表**，需用**真正含表格**的文档验证（见 `docs/问题与处理记录.md` D1 注记）。
- 对**无结构 / 多栏混排 / 扫描件（无文本层）**的文档，需调整解析与切片策略；本管线面向「单份公告型、有文本层」的文档。
