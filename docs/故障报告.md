# 故障报告 / 环境与运行错误记录

> 收录本项目在**本机环境搭建 / 运行管线**时遇到的**系统性故障**（现象 → 根因 → 解决 → 效果），以及**最终可运行的版本组合**。
> 供「换机器 / 复现 / 排障」参考；日常开发/设计内容不在此文档（见其它方案文档）。

**环境基线**：Windows 11 Pro (22H2)，i5-10210U，7.7GB 内存；统一在 `.venv_rag311`（Python 3.11）下运行。

| 组件 | 版本 | 关键点 |

## 二、故障与排查

### F1. chromadb 1.5.x（Rust 绑定）`add()` 段错误
- **现象**：`PersistentClient → create_collection → add` 时 `add()` 必然段错误（Windows `0xC0000005` / exit 139），`import`/建 client/建 collection 均正常。
- **定位**（faulthandler）：
  ```
  Windows fatal exception: access violation
    File chromadb\api\rust.py, line 484 in _add
    File chromadb\api\models\Collection.py in add
  ```
  崩溃点在 **Rust 原生绑定内部** `chromadb_rust_bindings.pyd`（PyO3 编译，随 chromadb wheel 捆绑）。
- **排查排除项**：中文路径（EphemeralClient+英文临时目录同样崩）、Python 版本（3.12/3.13 均崩）、版本单点（1.5.8 同样在 `_add` 崩 → 1.5.x 全线不可用）、指令集（AVX2 正常）。
- **解决**：改用 **chromadb 0.6.3（hnswlib 实现）** + Python 3.11。
- **效果**：`add`/`query` 全链路正常（`Permission`：`PersistentClient` 持久化路径 `data/chroma`）。

### F2. chromadb 0.6.3 `PersistentClient.add()` 批次边界崩溃
- **现象**：即使 0.6.3，当入库条数**跨过默认 `hnsw:batch_size=100`** 的「暴力检索缓存→hnsw 落盘」边界时，`add()` 仍 `0xC0000005` 空指针崩溃（Windows 弹窗「指令引用了 0x0000000000000000 内存」，无 traceback、缓冲 print 丢失）。
- **定位**：逐条单加，加到第 **100 条**必崩（= `hnsw:batch_size` 默认值）；已排除数据坏向量(NaN/Inf/零)、容量(`DEFAULT_CAPACITY=1000`)、`hnsw:num_threads=1`。
- **解决**：建集合时把 `hnsw:batch_size` 调成 **> 本次入库总条数**（`run_vectorize.py` 已改 `max(1000, len(chunks)+10)`）。
- **效果**：300+ 条 `add()` 成功 + 可 `query()`。

### F3. `EphemeralClient` 崩溃
- **现象**：0.6.3 的内存库（`EphemeralClient`）`add()` 在本机段错误。
- **解决**：**真实管线用 `PersistentClient`（`data/chroma`）**；排查/冒烟一律写 `PersistentClient`，别用内存库。

### F4. onnxruntime 1.29.0 DLL 初始化失败
- **现象**：`ImportError: DLL load failed while importing onnxruntime_pybind11_state: 动态链接库(DLL)初始化例程失败`。
- **连带**：chromadb 0.6.3 的 `DefaultEmbeddingFunction`（ONNXMiniLM_L6_V2）在模块级实例化 → 整个 `import chromadb` 失败。
- **佐证**：全局 3.13 的 onnxruntime 1.27.0 import 正常 → 坑集中在 1.29.0 新版。
- **解决**：降级 **onnxruntime 1.19.2**（Python 3.11 经典稳定版）。

### F5. posthog 遥测参数签名错误
- **现象**：`Failed to send telemetry event ...` —— 0.6.3 用老签名调 `posthog.capture(user_id, name, props)`，而 posthog 7.x 改成 `capture(event, *, distinct_id=…, properties=…)` → 参数个数错误 TypeError。
- **解决**：把 posthog 钉回 **3.x**（`posthog>=2.4.0,<4.0.0`），配合 `anonymized_telemetry=False` 自动 `posthog.disabled=True`，无需 monkeypatch（原 `_silence_chroma_telemetry()` 已从脚本移除）。`CHROMA_TELEMETRY_ENABLED=false` 在 0.6.3 源码里不读取、**无效**。

### F6. torch / onnxruntime 本地不可用 + 国外网络不通（本机硬约束）
- **现象/约束**：
  - `torch`、`onnxruntime` 在**全局 Python 3.13** 下 DLL 初始化失败；`sentence_transformers`（依赖 torch）、本地 `hnswlib` 不可用。
  - **国外网络**（HuggingFace / OpenAI / PyPI 直连）超时；仅**国内可达**（DashScope、阿里云 PyPI 镜像 `mirrors.aliyun.com/pypi/simple/`）。
  - 沙箱环境阻止 `pip install` / 建 venv（`ensurepip` 写临时目录 `PermissionError`），装包/换版本需在**沙箱外**（用户终端）进行。
- **解决方案**：embedding/生成走**云端 API**（DashScope）；依赖装包在用户终端用 `uv pip install`（带版本约束）；默认 ONNX 嵌入函数因需联网下载模型而**弃用**，改为**显式传 embeddings**。

### F7. 模型名与配置注意
- 模型名走 `DASHSCOPE_EMBEDDING_MODEL`（默认 `qwen3.7-text-embedding`）。`.env` 与 `embedding/dashscope_embedder.py` 默认值一致。
- 文档若出现 `text-embedding-v3/v4` 一律视为**备选/对比**，**勿据此改 `.env`**（否则索引端/检索端向量不在同一空间）。

## 三、其它注意事项（运维向）
- collection 名称规则（chromadb 0.6.3 起）：3–512 字符、`[a-zA-Z0-9._-]`；`'t'` 这类短名会报 `InvalidArgumentError`。
- chromadb 默认 embedding function（ONNX MiniLM-L6-V2）首次使用需联网下载模型；本项目惯例是**显式传 `embeddings`**。
- 建议用 `uv pip freeze > requirements.txt` 固化版本，避免裸装回退。
