# RAG 向量化方案（压缩摘要）

> 说明：本文件是「切片方案要点 + 向量化最终选型」的**压缩摘要**。调试/排查过程（chromadb 崩溃定位、numpy 假设、uv/venv 搭建、faiss 尝试等）已省略，仅保留结论性方案与选型，供实现与回顾使用。

---

## 一、切片方案要点

- **切片器**：`chunking/chunker.py`（结构感知混合切分），读数据准备产物 `data/processed/*.jsonl`（每行一个 `Block`，`kind=heading/para/table`），**直接按 `kind` 判边界**，不从 Markdown 反推。
- **规则**：标题为一级边界（维护标题栈得 `section_path`）；**表格整体不可拆分**；段落按目标大小聚合（`chunk_size≈300`）；超长段落按句切（不切半句）；过短片段回并（`min_chunk≈100`）；大小驱动切点附**句边界 overlap**（`overlap_ratio≈15%`）；`attach_heading` 把标题上下文并入 `text`。
- **Chunk 结构**：`id / doc / section_path / text / rows / start_block / end_block`（2026-08 精简：`kind_comp/char_len/overlap` 已移除，后段不消费且 `kind_comp` 徒增一次 `json.dumps`）。`text` = 真正拿去向量化的字符串（含标题前缀 + overlap + 换行段落边界）。
- **产物**：`data/chunks/*.chunks.jsonl`；不改动原文档与数据准备产物，靠 `doc + section_path + start/end_block` 回溯。
- 详细设计见 `docs/切片方案.md`。

## 二、向量化最终选型

### Embedding 模型
- **阿里云 DashScope `qwen3.7-text-embedding`**（千问 Qwen3.7 通用文本向量，实测可用、1024 维；与 `text-embedding-v3` 同为真实模型，本方案统一用它）。备选：`text-embedding-v4`。
- 模型名做成 `DASHSCOPE_EMBEDDING_MODEL` 可配置（默认 `qwen3.7-text-embedding`）。
- 接口：`POST https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings`（OpenAI 兼容），`Authorization: Bearer <key>`，body `{model, input:[...], dimensions, encoding_format:"float"}`；单次批量≤10 行、单行≤8192 token。本机 `requests` 可连通。

### 向量库
- **chromadb 0.6.3（hnswlib 版）**。
- 原因：`chromadb 1.5.x` 的 **Rust/PyO3 绑定在这台 Windows 上 `add()` 必段错误（0xC0000005 access violation）**，不可用（已实测排除 numpy 版本、中文路径、Python 版本等因素）。
- 可用组合：**Python 3.11 `.venv_rag311` + chromadb 0.6.3 + chroma-hnswlib 0.7.6 + numpy 1.26.4 + onnxruntime 1.19.2**，add/query 全通过；版本锁定原因与排障见 `docs/故障报告.md`。
- 运行环境：`.venv_rag311\Scripts\python.exe`（`.venv_rag` 这个 3.12 版已弃用）。

### 入库映射（回答"如何与原切片对应"）
- 把 chunk 的 `id` + 溯源元数据（`doc / section_path / start_block / end_block`）**一并写入 chromadb 那一行** `{id, embedding, text, metadata}`（2026-08 已去掉 `kind_comp/char_len/overlap`）；
- 检索命中后用 `id` 回映射到原 chunk，再靠 `doc + section_path + start/end_block` 回溯回原文档。

### 注意事项
1. **升级 chromadb 前必须测试**：1.5.x（Rust 绑定）在此 Windows 不可用；官方修复后再考虑升级。
2. **`uv pip install` 必须带版本约束**：裸装会把 onnxruntime 拉回 1.29.0 导致 import 崩溃。
3. **collection 名称** ≥3 字符、`[a-zA-Z0-9._-]`，如 `rag_chunks`。
4. 遥测告警（0.6.3 用老签名调 `posthog.capture`，posthog 7.x 签名不匹配会抛 TypeError，无害但碍事）**治本**：把 posthog 钉回 **3.x**（`posthog>=2.4.0,<4.0.0`），`anonymized_telemetry=False` 自动 `posthog.disabled=True`，无需 monkeypatch（原 `_silence_chroma_telemetry()` 已移除）。`CHROMA_TELEMETRY_ENABLED=false` 在 0.6.3 源码中不读取，无效。
5. **始终显式传 embeddings**，不依赖默认 ONNX 嵌入函数（避免联网下载/依赖坑）。
