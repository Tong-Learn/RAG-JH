### P0 —— 上简历前必须做（合计 2~3 天）

#### P0-2 数据准备·去重 【MEMORY 原待办，此前漏列】
- **事实依据**：`docs/问题与处理记录.md` B6——**21 处重复正文**：公告把常规服+赛季服两段放同一页，开头「亲爱的冒险者：为了给冒险者们提供更好的体验…」「维护更新前已创建角色…」**重复两遍**；8月12日还有「自从现文明观星学发现…」×2。影响：检索命中重复片段，稀释 precision@k。
- **最小实现（按已定原则「安全去重」）**：在 `cleaner.py` 或 `pipeline.py` 加**内容级精确去重**——规范化后**完全一致的 para 才删**；高度相似**只标记不删**（manifest 里记 `dup_of`/`dup_count` 字段）。零误删风险。
- **进阶（可选，别急着做）**：对 578 个 chunk 跑一遍 embedding 余弦相似度分布，看近似重复簇，据此再定阈值。SimHash/MinHash 是面试谈资，这个量级用不上——**相似 ≠ 重复**（版本差异、同主题不同文档不能乱删），这句是面试金句。
- **验收**：重复数从 21 → 0（精确级）；precision@3 前后对比记录进 `docs/问题与处理记录.md` B6 的「处理效果」。
- **面试价值**：现成的「我发现并处理了自己数据的坑」故事：21 处重复 → 稀释答案密度 → 安全去重策略及理由。

#### P0-3 溯源坐标生产化 【MEMORY 原待办】
- **现状**：`start/end_block` 是块下标，README 承诺的「附原文链接」兑现不了。
- **分两步走**（先易后难）：
  1. **页码**：`extract_pdf()` 改 `for pno, page in enumerate(doc)`，`Block` 增加 `page: int = 0`，pipeline/chunker 透传，chroma metadata 加 `start_page/end_page`；`run_rag.py` 引用附录输出「来源：文档名 §section (p.X)」。
  2. （可选）`start_char/end_char` 或 `source_uri`：字符偏移在段落合并时维护成本高，页码已满足「可回溯」；别为了简历动词过度工程。
- **验收**：抽 3 个回答，页码人工核对正确。

#### 新增-1 相似度阈值 + 拒答 ⚠️ 最高优先级
- **为什么**：`docs/面试要点.md` 写了「相似度阈值」是兜底手段，但 `run_rag.py` 的 `retrieve()` 没实现——**文档承诺了、代码没有**，被追问当场处刑。同时它是幻觉防线第一层。
- **最小实现**：`retrieve()` 已算 `score = 1 - dist`，加 `min_score` 参数；hits 为空或最高分不达标 → 输出「资料中没有相关信息」，**不调生成 API**。
- **阈值校准方法**（面试会问）：评测集 31 题（23 可答 + 8 无答/无关）跑 top-1 分数分布（正类）+ 语料无关问题（负类），取两分布间谷值。
- **验收**：31 题（23 可答）全部正常回答；8 个无答/无关题 ≥90% 被拒答。实测：阈值 0.70 下拒掉 7/8 负样本（1 个游戏邻域无答题 0.719 越过閾值）。

## 第二部分：被问到「没做过的东西」怎么答

### 心法（先立住）

面试官问你没做过的功能，考的不是你做没做过，而是三样：**①诚实度 ②知识面 ③现场设计能力**。编造是唯一错误答案——追问两层必穿，穿了一个项目全变假的；而且这个项目最大的卖点就是「诚实评估」人设，编一个功能等于自己拆自己的人设。

### 万能框架：「认 → 桥 → 构 → 验」四步

| 步 | 时长 | 做什么 |
|---|---|---|
| **认** | 5 秒 | 直接承认：「这个我在项目里没有做，我直说。」不绕、不装 |
| **桥** | 30 秒 | 拉回真做过的最近似问题：「但项目里有个很近的问题我真踩过：…当时方案是…」 |
| **构** | 1~2 分钟 | 现场给方案：「如果要做，我会…」需求 → 方案 → 为什么 → 取舍。**用本项目的真实约束说话**（小语料/中文/本机无 torch/成本敏感），比背通用八股强十倍 |
| **验** | 15 秒 | 收尾：「做完用评测集回归，看 recall/拒答率变化；这个方案的风险是…」 |

**反例**（自杀式）：「啊这个我没考虑过……」然后沉默/现编一个「我们当时用了……」。
**正例**：「并发这块我没设计——它是批处理管线，不是在线服务，这是我有意的范围控制。如果服务化，瓶颈在 embedding API 延迟，我会加查询向量缓存和异步批量；检索本身 578 条暴力都够，chroma 的 HNSW 是留扩展余量。」

### 分题型话术

**题型 A：「XX 功能是怎么设计的？」（你有近亲实现）**
公式：「我项目里对应的设计是 X，它解决同一类问题里的 Y 部分；你说的 XX 我没单独做，但基于 X 我会这样扩展…」
例：问「查询改写怎么设计」→「我没做查询侧改写；我做的是文档侧补上下文——chunk 拼接时把 `section_path` 标题前缀加进向量化文本。查询侧的对应手段是改写/扩写，接进来是一层 prompt 的事。」

**题型 B：「XX 问题你是怎么解决的？」（你没踩过这个坑）**
铁律：**不编故事**。「这个坑我确实没踩过」+「但我排查问题的顺序是一致的：检索侧→数据侧→预处理→切片→生成侧」+「如果遇到，第一步我会…（给可操作定位手段：打印中间产物 / 对拍 / 二分）」。

**题型 C：「为什么不用 XX 策略/框架？」**
公式：承认 trade-off → 当时的真实约束 → 现在的接入计划。**不贬低不用的东西**。
例：「为什么不用语义切分」→「我在 docs 里设计过『用向量定切点』，留作第二版：我的语料是高结构化公告，标题就是天然切点，语义切分预期收益小、成本（逐句 embedding）高；换无结构长文我会启用。」

**题型 D：底层原理答不上（如 HNSW 推导）**
分层承认：「HNSW 我知道到『分层近邻图 + 贪婪搜索』这一层，ef/M 参数调过；推导层面没深入，这在我学习计划里。我实际处理过的是工程面：cosine space、distance 转相似度、以及 578 规模下其实暴力检索就够。」
万能兜底：「这个点我没深入到能现场推导的程度，不想现编一个错的给您。我能确定的是……」

### 本项目最可能被问的「没做过的点」× 12 逐条脚本

| # | 可能的问法 | 事实 | 60 秒答辩要点 |
|---|---|---|---|
| 1 | 并发/性能怎么设计的 | 无并发设计 | 「批处理管线非在线服务，是范围控制。性能意识体现在：embedding 批量 ≤10（DashScope 上限）、失败退避重试、全量幂等重建。服务化后瓶颈在 embedding API 延迟 → 查询向量缓存 + 异步批量；578 规模检索暴力都够，HNSW 是余量」 |
| 2 | 增量更新怎么做 | 全量幂等重建 | 「578 chunk 秒级、幂等最可靠——是规模下的正确取舍。增量方案已想好：manifest 对比源文件哈希，只重跑变更文档，chroma 按 doc 先删后插。一晚上的活，没做是因为语料静态、收益为零」 |
| 3 | 部署/多用户 | 无，CLI | 「CLI 是刻意的最小闭环。服务化第一步 FastAPI 包一个无状态 /ask；无会话状态所以横向扩展天然容易；再往后限流 + 缓存」 |
| 4 | 权限/数据安全 | 无权限设计 | 「处理对象是公开公告，无权限是有意的范围控制。企业落地用 metadata 预过滤：检索前按用户 ACL 过滤 doc 集合，而不是检索后过滤——后过滤会破坏 top-k 语义」（能说出 pre/post filter 区别即加分） |
| 5 | 扫描件/图片 PDF | 只支持文本型 PDF | 「这是明确边界，README 写了。扫描件路径：OCR（PaddleOCR）→ 版面分析（Docling/LayoutLM）→ 接回我的 Block 层——Block 是格式无关中间表示，这正是做这层抽象的原因」（短板转成架构伏笔） |
| 6 | 为什么 chroma 不用 milvus/faiss/pgvector | 规模小 | 「578 条数据什么库都是杀鸡用牛刀；选 chroma 是零运维 + 持久化 + metadata 过滤够用。千万级换 milvus 或 pgvector（业务已有 PG 时）；faiss 是库不是服务。选型跟着规模走，不跟着简历关键词走」 |
| 7 | chunk_size=300 怎么定的 | 经验值 | 「初始是经验值（对应公告段落量级），是合理起点不是调优结论；参数已全部可配，网格实验在计划里（P2-3）。我刻意避免疯狂调参——31 题的小评测集，调狠了评测集就变成训练集」（此句必背） |
| 8 | 表格检索质量怎么保证 | 表格整体成 chunk | 「表格不拆、rows 原始行列进 metadata、拼接保『\|』结构、前缀 section_path。已知局限：合并单元格/跨页表处理不了。改进：行级展开成自然语句或表格摘要」 |
| 9 | top-k=4 怎么定的 | 经验值 | 「300 字 chunk × 4 ≈ 1200 字上下文，在 qwen3.8-max 里便宜且不稀释。严格定法是拿评测集扫 k=1..8 看 end-to-end 引用准确率——和生成侧评估（P2-4）一起做」 |
| 10 | RAG 和 Agent 怎么结合（岗位对口必问） | 未接入 | 「两层：①检索包装成 tool，agent 决定查不查/查什么/查几轮（agentic RAG）；②阈值+拒答输出作为 agent 的『可信度信号』，不够就触发 query 改写重检。我现在做的拒答机制就是给 agent 化打地基」 |
| 11 | 成本/延迟 | 无缓存 | 「embedding 是一次性批处理成本，可忽略；在线成本在生成侧（max_tokens 1024、temperature 0.3）。服务化后第一个加 query 向量缓存 + 热门问题缓存」 |
| 12 | 多轮对话怎么做 | 单轮，有意裁剪 | 「多轮核心新问题是指代消解（『它』几号开的？）。标准做法：改写层用小模型把指代展开成实体再检索；会话记忆用 LangGraph checkpointer。与 Agent tool 化是同一套东西，在路线图里」 |
| 13 | 语料里有重复内容怎么办 | B6 已记录 21 处 | 「扫过：常规服/赛季服同页问候语重复 21 处，会稀释 precision@k。策略是安全去重——规范化后完全一致才删、近似只标记不删，因为『相似≠重复』；阈值类激进方案要等相似度分布数据。做完拿 precision@3 前后对比验证」（若已做完 P0-2，直接报数字） |
