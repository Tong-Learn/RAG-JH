# RAG 面试要点与设计心得

> 本文档沉淀本项目对 **RAG 标准化流程**的理解、**每步的「我的思考 / 解决思路 / 延伸思考」**，以及**面试级回答口径**。这是**面试深挖的核心**，也反映了本项目的设计取舍。
> （日常实现/参数见各方案文档；环境与故障见 `docs/故障报告.md`。）

---

## 一、定义与目的

**RAG = 检索增强生成**，用于解决**大模型幻觉**、大模型对企业真实文档数据缺失等问题：
> 外部文档先**检索**出相关片段，拼进上下文，再让模型**基于检索资料**回答 → 让模型「有据可依、可溯源」，减少瞎编。

---

## 二、标准流程（5 步）

```
源文档 → 【数据准备】提取+清洗+统一结构 → 结构感知切片 → 向量化(embedding+入库)
        → 【检索】同源向量化+相似度top-k → 【生成】拼上下文+带引用回答
```

---

## 三、逐步骤讲解 + 面试级回答

### ① 数据准备：提取 → 清洗 → 统一中间表示
- **做什么**：把 Word/PDF/Excel/PPT/txt/md 解析成干净结构化内容。各格式用对应库：Word→python-docx、PDF→PyMuPDF、Excel→openpyxl/pandas、PPT→python-pptx、txt/md→标准库。
- **保留结构（关键）**：不只拿文字，还要**标题层级 / 表格**。定义 `Block(kind=heading/para/table)` 作为统一中间表示——用**语义标签**承载结构，而非裸文本；`md` 仅作**人工核对**展示层。
- **面试级回答**：“我不把文档转成 Markdown，而是按原格式直接解析、用带类型的 `Block` 保结构；因为转 md 有损、会把表格拉平，而表格常是‘事实型问题’的答案所在；这也更贴近工业界（Unstructured/Textract 返回类型化元素）。”
- **延伸思考**：清洗要规范化（编码、全角/半角、空白压缩）+ 去噪（页眉页脚、页码、HTML 注释、空块）。

### ② 切片：结构感知（而非固定大小）
- **做什么**：把内容切成适合向量化+检索的最小单元（chunk）。直接读 `Block.kind` 判边界——标题为一节边界（维护标题栈得 `section_path`）、**表格整体不可拆**、段落按目标大小聚合、超长**按句切（不切半句）**、过短回并、切点附「句边界 overlap」。
- **面试级回答**：“我不做固定大小硬切（`RecursiveCharacterTextSplitter` 会切碎语义），而是沿语义边界切：标题、句子、表格都不拦腰截断；并保留一段**句边界重合(overlap)**，防止关键语义/问句被切在两块之间。”
- **我的思考**：切片后原文档保持原样，还是存成切片后样式？
  **解决思路**：**原文档与数据准备产物一律不动**；切片是**新增下游产物**，单独落盘（`data/chunks/*.chunks.jsonl`），靠 `doc + section_path + start/end_block` 回溯。
- **延伸思考**：能否「先向量化再切片」？——**入库向量必须切片在前**（embedding 按文本单元算，整篇向量切不开）。但可做「**用向量定切点**」的**语义切分**（按句嵌入、相邻相似度骤降即断层），与结构感知互补；本项目留作第二版增强（只对无结构长文启用）。

### ③ 向量化：embedding + 向量库
- **做什么**：把 chunk 用 embedding 模型转向量并写入向量库，供相似度检索。
- **选型**：DashScope `qwen3.7-text-embedding`（1024 维，OpenAI 兼容接口）；向量库用 **chromadb 0.6.3（hnswlib）**（`hnsw:space=cosine`）。
- **一致性（关键）**：检索必须用**同一模型**、对**同一格式文本**编码，否则向量不在同一空间。
- **面试级回答**：“我把 chunk 的 `id` + 全部溯源元数据**一并写进向量库那一行**（`doc/section_path/start_block/end_block`）；检索命中后用 `id` 回映射回 chunk，再靠 `doc+section_path+start/end_block` 回溯回原文档，天然满足「附原文链接」。”
- **延伸思考**：① 为何不用默认 ONNX 嵌入函数？——默认函数首次使用要联网下载模型、模型/维度/归一化不可控，与检索端一致性难保证，故**显式传 embeddings**。② 为何排除本地模型（sentence_transformers/torch）？——本机 torch/onnxruntime DLL 初始化失败、国外网络拉不下 HF 权重；若换机器可优先本地小模型纯离线。

### ④ 检索：同源向量化 + top-k
- **做什么**：用户提问 → 用**同一** embedding 模型编码 → 向量库余弦匹配 → top-k 片段。
- **余弦相似度语义**：cosine 空间 `distance` 越小越相似（0=完全一致，2=完全无关），展示常用 `1 - distance` 作为「相似度」。
- **结构感知增益**：检索返回的是**带结构坐标的 chunk**（`doc + section_path + blocks`），能给出「从哪份文档、哪个章节、哪几块找出来的」，更可信、更易溯源。
- **我的思考**：直接拿 top-k 去回答够吗？会不会检索到「相似但错误」的片段？
  **解决思路**：**先检索、再回答、中间加兜底与校验**——① 限定「仅依据检索资料作答，资料没提就如实说明」，从 prompt 层避免幻觉；② 相似度阈值 + 溯源引用（`[1][2]` 指向实际片段）；③ 后续加 rerank / 混合检索（向量+BM25 取并集）/「无相关信息」拒答口径。
- **延伸思考**：为什么检索结果可能「相似但不对」？——向量匹配本质是**语义相似**而非**事实匹配**：整段讲「团本材料」的文档，向量会与「团本材料怎么获得」高度相似，但可能不直接回答该问题（RAG 固有短板，也是需评估与 rerank 的原因）。

### ⑤ 评估：可量化指标 + 有标准答案的评测集
- **检索侧指标**：`recall@k`（答案所在文档是否出现在 top-k）、`MRR`（答案第一次出现位次倒数平均）、衍生 `precision@k`/`nDCG`/`hit-rate`。
- **生成侧指标**：`faithfulness`（忠于检索资料）、`answer relevance`（答案切题）、上下文精确率/召回率（参考 RAGAS）。本项目先做检索侧，生成侧以人工核验为主。
- **评测集构造**：`问题 + 标准答案`。**必须「问题天然来自语料、且答案唯一可定位」**——若语料里根本没答案，检索不到是合理的，会拉低指标但不代表系统差。所以从每份文档真实内容反推问题，避免「用主题直接造题导致命中率虚高」。
- **我的思考**：只用 recall@k/MRR 够吗？小语料 + 按主题造题，指标会不会虚高？
  **解决思路**：**认清并控制「评估的真实性」**——① 指标必须配**语料规模 + 问题难度**一起看：小语料下 top-5 几乎必然命中，`recall@5=1.0` 只是**合理基线**而非「系统很强」；② 要有说服力须扩真实语料 + 造更硬的问题（跨文档辨析、语义近似但答案不同、语料中确无答案的题）；③ 指标从**文档级**细化到 **chunk/句级**；④ 用评估是为了**定位短板**，不是刷数字。

---

## 四、常用指标速记

| 指标 | 含义 |
|---|---|
| recall@k | 答案是否出现在 top-k（命中率） |
| MRR | 答案第一次出现位次的倒数平均 |
| precision@k | top-k 中来自答案文档的占比（答案密度） |
| nDCG@k | 位置折扣：越靠前得分越高 |
| P@1 | top-1 即命中答案 |

## 五、效果不好时，排查顺序（面试高频）

> 先**检索侧**（是否召回正确片段）→ 再**数据侧**（文档是否有答案/重复/过期）→ **预处理侧**（提取是否干净）→ **切片侧**（粒度），最后才是**生成侧/提示词**。**检索侧出错，生成再好也白搭。**

## 六、本项目的「刻意对照」卖点

| 本项目做法 | 主流/LangChain 默认 |
|---|---|
| 原生格式直接解析 + `Block(kind=...)` 保结构 | 复杂文档用 Unstructured/Docling 返回类型化元素 |
| 结构感知切片（标题栈/表格整体/按句切/overlap/过短回并） | 常为固定大小 / `RecursiveCharacterTextSplitter` |
| 一套自研可审计产物（jsonl + md + manifest + chunks + chroma 行） | 常直接 Loader→Document→切片→入库，无中间层 |
| 评估诚实性：小语料高指标仅视为合理基线 | 区分「真实指标」与「小语料自嗨」 |
| 完整踩坑溯源（chromadb 段错误 → 锁 0.6.3、batch_size 边界崩溃等） | 体现工程排障（见 `docs/故障报告.md`） |
