## 1. ② 溯源坐标生产化 + 回答附原文档标识（✅ 已完成）

**目标**：每个 chunk 能回溯到「文档 + 段落 + 页码」；生成回答（过阈值时）的引用里带**原文档标识 + 页码**。

**改动点（字段 + 文件）**：
| 文件 | 改动 |
|---|---|
| `preprocessing/extractors.py` | `Block` 加 `page: int = 0`；`extract_pdf()` 改 `for pno, page in enumerate(doc)`，每个 Block 带 `page=pno+1`（第X页，1-based）。txt/md/docx/xlsx/pptx 置 `page=0`（无页码，后续如需再补）。 |
| `preprocessing/cleaner.py` | `clean_blocks` **透传** `page`（drop/合并时不丢该字段）。 |
| `chunking/chunker.py` | `Chunk` 加 `start_page: int=0` / `end_page: int=0`；`make_chunk` 用 `block_idxs` 内各 block 的 `page` 取 min/max。block 是 dict，读 `b.get("page")`。 |
| `scripts/run_chunking.py` | 无需改（`c.__dict__` 自动带出新字段）。 |
| `scripts/run_vectorize.py` | `chunk_to_record` 的 metadata 加 `start_page`/`end_page`。 |
| `scripts/run_rag.py` | 引用附录「来源」行输出 `[i] 文档名 §section_path (p.X~Y)`；符合阈值时展示。 |

**验收**：抽 3 个回答，人工核对页码正确；`query_retrieval.py` 检索结果也带 page。

**注意**：`section_path` 是标题路径，`page` 是另一回溯维度；两者都进 chroma metadata。`extract_pdf` 已有 `page.rect`，页码取 `enumerate` 的下标 +1 即可，无需版面分析。

## 2. ① 相似度阈值 + 拒答（✅ 已完成，校准 0.70）

**目标**：检索质量低于阈值 → 拒答「资料中没有相关信息」，**不调生成 API**（省成本、防幻觉）。

**改动点（`scripts/run_rag.py`）**：
1. `retrieve()` 增加 `min_score` 参数（现已有 `score = 1 - dist`，cosine）。
2. 拒答判定：`hit 为空` **或** `hits[0].score < min_score` → 拒答。可同时参考 top-1 与均值，但**先以 top-1 为准**。
3. 拒答响应：输出「资料中没有相关信息（top-1 相似度 x.xxx < 阈值 y.yyy）」；**return，不调 `chat()`**；并打印最接近的 chunk 供人判断（透明）。
4. 常量：`run_rag.py` 顶部 `DEFAULT_MIN_SCORE`；`main()` 加 `--min-score`。
5. **阈值校准（关键，防止拍脑袋）**：
   - 正类：评测集**可答**题目跑 top-1 相似度分布。
   - 负类：**语料无关题**（领域外）+ **语料无答案题**（来自 ⑤）跑 top-1 分布。
   - 取两分布之间**谷值/分界**为阈值，记录进 docs。
   - 经验参考（以实测为准，不预设）：语料内相关题 top-1 常 ≥0.6，语料无关题 <0.5，阈值约 0.55~0.65。

**验收**：①可答题全部正常生成（无误拒）；负样本题 ≥90% 被正确拒答。

**联动**：拒答输出可作为后续 **agent 化的「可信度信号」**（不达标 → 触发 query 改写重检）。

## 3. ③ 新增问答样例（两套评测集）（✅ 已完成，18+13 题）

**目标**：建 basic + complex 两套评测集，作为检索质量基线 + 优化对比基准。

**两个文件（受版本控制，放 `data/eval/`）**：
- `data/eval/qa_basic.jsonl` —— **常规集**：正常(可答) + 错误(语料无答案) + 无关(领域外)。
- `data/eval/qa_complex.jsonl` —— **复杂集**：跨文档辨析 + 语义近似但答案不同 + 精确词/数值类 + 需 rerank 才能拉回的题。

> 说明：`test/` 语料在扩充中。若本轮新增的语料本身就是「两份公告」，这两套评测题就围绕新增语料 + 既有语料来出，覆盖上述题型。
> 「两个测试文档」我按**两套评测集**理解（便于分别出基线/优化指标）；若你其实是说**新增两份语料文档**，请告知，我按语料出题。

**条目 schema（扩展现状 `{query,expected_doc,note}`）**，每行：
```json
{
  "id": "c01",
  "set": "basic" | "complex",
  "category": "answerable" | "unanswerable" | "irrelevant",
  "type": "normal" | "cross_doc" | "semantic_close" | "exact_term" | "no_answer" | "off_topic",
  "query": "...",
  "expected_doc": "答案所在文档（可答类必填）",
  "expected_section": ["...", "..."],
  "expected_chunks": ["chunk_xxxxxx", "..."],
  "expected_page": [1, 2],
  "note": "...",
  "hard": true
}
```

**各题型要点**：
| type | 设计意图 | 靠什么优化生效 |
|---|---|---|
| `cross_doc` | 答案在 A 不在 B（如「征战之塔第一期 vs 第二期」） | 混合检索/rerank 拉回正确文档 |
| `semantic_close` | 措辞相似但答案不同（第6赛季 vs 第7赛季） | 精确词命中（BM25）+ 重排 |
| `exact_term` | 含专名/数字/价格 | BM25 关键词优势 |
| `rerank` | 正确 chunk 在向量 top-k 之外 | rerank 拉回 |
| `no_answer` | 语料无答案，应拒答 | 与 ① 联动，验拒答率 |
| `off_topic` | 领域外（游戏外问题），应拒答 | 与 ① 联动 |

**题数建议**：basic 20~30（normal 15 / no_answer 5~8 / off_topic 5~8）；complex 20~30（cross_doc 5~8 / semantic_close 5~8 / exact_term 5~8 / rerank 5~8）。合计 ~50~60 题。

**标注**：题目定稿后需 **ground-truth**（expected_doc / section / chunk / page）。这一步要跑现有管线拿到 chunk 分布再人工核对；等新语料 + 溯源（②）+ 切片完成后再标。

## 4. ⑤ 精确检索 BM25 + 混合检索 + rerank（✅ 已完成，complex P@1 0.846→1.0）

**目标**：在 `qa_complex` 上对比三档指标，突出优化效果：
- **A 基线**：纯向量 top-k
- **B 混合**：BM25 top-N ∪ 向量 top-N → RRF 融合
- **C 混合+rerank**：B 的 top-N → rerank → top-k

**依赖**（需 uv 安装）：`rank_bm25`、`jieba`（中文分词）；rerank 用 **DashScope API**（本机 torch/onnxruntime 有崩溃前科，见 `docs/故障报告.md`，故用 API）。

**改动点**：
| 文件 | 改动 |
|---|---|
| 新增 `retrieval/hybrid.py` | BM25 索引（`jieba.cut` 分词 corpus，可持久化 `data/bm25_index.pkl`）+ `bm25_search()` + `vector_search()`（复用 chroma）+ `rrf_fuse(a,b,k=60)` |
| 新增 `retrieval/reranker.py` | `rerank(query, candidates)` 调 DashScope `qwen3.7-text-rerank`，返回重排 top-k + relevance |
| `scripts/eval_retrieval.py` | 支持 `--mode vector_only|hybrid|hybrid_rerank`；对 basic/complex 分别出指标；加**拒答率**/无答案题正确拒答比例（与①联动） |
| `scripts/run_rag.py` | 可选加 `--retrieval mode` 让生成侧也走 hybrid/rerank |

**指标**：recall@k / precision@k / MRR / P@1 / nDCG@k（对 basic、complex 分别），外加拒答率。

**验收/记录**：把三种模式的对比表写进 docs（如 `docs/问题与处理记录.md` 或本方案附录）。**诚实标注**：若复杂集提升有限，如实报并分析（小语料/基线已高/专名分词不准）。

**风险**：
- `jieba` 对游戏专名可能切不准 → 影响 BM25；可加自定义词典（专名/装备/价格）。
- DashScope `qwen3.7-text-rerank` 为用户指定模型，执行时**先探活**（小调用确认模型名有效）；若无则换其它 rerank API。
- rerank 有成本/延迟 → 候选控制在 top-20 → rerank → top-4。
