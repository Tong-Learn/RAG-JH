### 5.2 口径说明

1. 四指标在**全部 60 题**上平均（不可答题贡献「拒答正确性」），与检索侧只在 **54 题**上算**不对称**。
2. 打分输入是「问题 + 标准答案 + 是否可答 + 检索资料 + 系统回答」；`evidence` 字段不参与打分。
3. 「拒答正确性」对**可答题**看是否被误拒、对**不可答题**看是否拒答；对可答题给出拒答话术直接计 0。

### 5.3 与历史不可比（务必不要横向比数）

本轮同时改了四件事：**提示词**（强制统一拒答话术）、**判分模型**（`qwen3.8-max` → `qwen3.7-flash`）、**题库**（50 → 60 题、不可答 3 → 6）、**k**（3 → 5）。因此忠实度 / 引用率的下降主要来自结构而非能力：引用 0 分的 11 题里 **6 题是被阈值拦下的不可答题（回答为固定拒答句、天然无引用）**、另有 C11 / C25 两题是拒答句、3 题（C23 / C24 / C27）是**真的整段未标注引用**——即「拒答类回答没有引用被计 0」与「回答确实漏标注引用」各占一部分。**拒答正确性与答案正确率更有参考意义**。

## 7. 错例分析（混合 + 重排路线，10 例）

挑题标准：答案正确率 ≤ 0.5 或拒答正确性 = 0 的题，按失分总量排序取前 10。归因分类为 **检索未覆盖**（正确来源文档没进 top-5）/ **检索到了但用错**（文档进了池子、chunk 不对或排序不利）/ **误拒**（资料够却拒答）/ **整合不足**（资料够、答得不全或有细节错）。

- **细节笔误类失分（C04、C15）不是检索或拒答问题**，是年份等短事实的对齐能力；这类题分数只到 0.5，属于「部分正确」的合理定价，但也说明 0.5 档里混有两种不同性质的问题（缺内容 vs 写错字）。

## 9. 综合结论

- 综合均值（simple recall@k / complex recall@k / 答案正确率 / 拒答正确性）：**混合+重排 0.890**，纯向量 0.766（四项分别为 1.000 / 0.809 / 0.817 / 0.933 与 0.926 / 0.627 / 0.692 / 0.817）。本轮纯向量**连忠实度 / 引用都不再领先**。
- **重排 + 混合是当前最优组合**：检索四项（recall / MRR / P@1 / precision）与生成四项全部不低于纯向量。
- **阈值必须分路线校准**：重排把可答 / 不可答干净分离（0 误杀 0 漏拦），纯向量不能（两分布重叠，取 0.55 换 0 误杀、认下 4 漏拦）。
- 最明确的短板仍是 **complex（跨文档多跳）**：检索平均覆盖率 0.809，且覆盖不全直接拖低生成正确率（全覆盖 0.781 vs 部分覆盖 0.350）。
- 本轮新增的失效模式是**可答题误拒**（C25 四项全 0）：提示词加强对拒答链路有效（6/6 拦住不可答题），但对可答题产生了新的整段放弃风险，值得单独排查。

## 10. 诚实边界与已知缺口

1. **负类样本仅 6 个**：阈值标定的不可答类只有 6 题，正负类分布的两端由极少数题目决定（纯向量正类下沿 0.5760 来自 C06、上沿 0.8259 来自 S07；负类上沿 0.6426 来自 C29）。「0 误杀 0 漏拦」应读作「在这 6 个负样本上如此」，不足以支撑生产结论。
2. **LLM-as-judge 偏差**：四指标由 `qwen3.7-flash` 打分，非人工盲评；0 / 0.5 / 1 是有序等级，直接算术平均隐含「等距」简化。判分理由本身也有噪声（例如 C04 的 `notes` 出现「2025误作2025而非2026」这类自相矛盾表述）。
3. **complex 正确率偏低**：混合+重排 complex 答案正确率仅 0.667，纯向量 0.450；跨 1~4 篇来源的多跳问题，单轮 top-5 + 生成难以覆盖全部要点（第 6 节）。
4. **3 份无署名文档的宣传尾巴残留 5 块**：尾部截断规则（块以「冒险者协会」结尾即丢弃其后块）对 3 份完全没有署名的文档无效，其宣传尾巴仍入库：「冒险传承」系统优化（2 块）、家园偷菜？温泉浴盐？…（1 块）、还能抢装备？…（2 块），共 5 块，占全库 607 块的 **0.8%**。已确认不影响任何一道题的答案；要清掉只能另开机制（手工块清单），本轮按已定口径接受。
5. **四路消融未复验**：见第 3 节——那组数字来自 54 份语料 / 50 题 / simple 集 k=3 的另一轮，口径同但语料与题库不同，**不可与第 2 节直接比较**。
6. **生成侧指标与版本绑定**：四指标绑定「提示词版本 + 判分模型 + 题库 + k」，四者本轮同时变过，与任何历史数字都不可直接比较（第 5.3 节）。
7. **检索指标有运行间波动，且产物快照来自不同次检索（本文已尽量隔离口径）**：同集同 k 重复检索时 top-k 内偶有顺序与分数差异，来自 embedding 服务与余弦并列排序。经逐题比对：
   - `retrieval_*.jsonl` 与 `threshold_*.json` 的 `per_question` **完全一致**，可视为同一次检索（本文第 2 节检索指标、第 4.1 分布、第 8 节明细表均取自此，内部自洽）。
   - `answers_*.jsonl` 是**另一次检索**：纯向量路线 60 题中有 **31 题** top-1 与上者不同（最大差约 0.003，如 S19 0.6792 vs 0.6764、S30 0.5003 vs 0.4975）；混合+重排路线 **60 题全部一致**，无差异。第 4.3 节的实测拒答取自此快照，**请勿与第 8 节明细表的 top1 数值混用**。
   - 差异均未越过任何决策边界（纯向量下 S29、C29 等仍在阈值同一侧，「拦 / 不拦」结论不变）；但换快照后个别紧贴阈值的题（如 S19 混合路线 0.6212、可答下沿）存在跨阈风险，复算请固定用同一份快照。
8. **检索是文档级、不是 chunk 级**：来源文档进了 top-5 不等于答对的 chunk 进了 top-5。C27 是明证——正确的加赠片段排第 2 位，生成仍抓错对象；S19 则是来源文档第 1 位但命中 chunk 恰好截断在奖励明细之前。**文档级 recall 会系统性高估「证据可用性」**。
9. **`evidence` 字段未参与打分**：打分基准是 gold answer + 检索上下文，评测集的 `evidence` 仅作参考。
10. **评测集为自建自评**：60 题由项目作者设计并标注来源文档，无第三方标注、无盲评。指标反映「系统能否回答这些既定问题」，不等同于「真实用户关心的问题被正确回答」。
11. **完整源语料不入库**：第三方可查看评测集与 `examples/` 样例产物，但无法在完整 60 题上复现本报告指标。
