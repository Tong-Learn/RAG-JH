# RAG 第一部分 · 数据准备：方案与代码实现

> 目标：把各种格式的源文档，经「提取 → 清洗 → 去噪 → 规范化」统一成一套**结构化语料**，
> 供下一步「切片」使用。本文档同时给出方案设计说明与配套代码。

---

## 1. 整体管线

```
源文档(Word/PDF/Excel/PPT/txt/md)
        │
        ▼  ① 提取  Parse(extractors.py)
   [Block, Block, ...] 结构化块
        │
        ▼  ② 清洗  Clean(cleaner.py)   —— 规范化 + 去噪 + 丢弃空块
   [Block, Block, ...] 清洗后块
        │
        ▼  (pipeline.py) 分别落盘
   ├─  *.jsonl   结构化语料(每行一个 Block)——数据准备的真输出，切片器直接读
   └─  *.md      渲染文本 —— 仅供人眼核对提取效果
```

三个阶段的核心代码都是**以"块"为单位**处理的：提取把各格式统一成块，清洗按块类型分别处理，
渲染按块类型选 Markdown 语法。这样结构在整条链路上不再丢失。

### 中间表示：Block（关键设计）

```python
@dataclass
class Block:
    kind: str                      # "heading" | "para" | "table"  ← 语义标签
    text: str = ""                 # heading / para 的正文
    level: int = 1                 # heading 级别(1=#, 2=##,...)
    rows: list = field(default_factory=list)  # table 的行(每行是字符串列表)
```

- **`kind` 是语义标签**（`"heading"/"para"/"table"`），只存在内存/JSONL 里，供程序判断。
- **`#`、`|` 不是标签**，只是把块写成 Markdown 时才出现的展示符号（`#`=标题、`|`=表格列）。
  反向解析时它们是"猜结构"的线索；程序真正依赖的是 `kind`。

## 2. 各格式提取策略（标题 / 正文 / 表格识别）

> 核心：**"能不能识别出结构"取决于源格式自己带不带结构**。所以同一套 Block，
> docx/md/pptx 能保留标题，而 txt 全是 `para`（它本就没有标题概念）。

| 格式 | 解析库 | 标题识别 | 正文 | 表格识别 |
|---|---|---|---|---|
| txt | 标准库+编码回退 | 无(视为段落) | ✔ 按空行分段 | 无(伪表格=文本) |
| md | 标准库+正则 | ✔ `#` 级别 | ✔ 连续行聚合 | ✔ `\| |` 管道表 |
| docx | python-docx | ✔ `Heading N` 样式 | ✔ 段落 | ✔ `Table` 对象 |
| pdf(文本) | PyMuPDF | 启发式(字号/加粗) | ✔ 文本块 | ✔ `find_tables()` |
| xlsx | openpyxl/pandas | 无(标题=单格行) | ✔ | ✔ 行列结构 |
| pptx | python-pptx | ✔ 标题占位符 | ✔ 形状文本 | ✔ `has_table` |

### 2.1 txt —— 最简单，但无结构

- 编码回退：`utf-8 → gbk → gb18030`，避免中文乱码。
- 按**空行**切段落；把连续非空行合并成一段。
- 因无结构，所有内容标为 `para`。

```python
def extract_txt(path):
    raw = _read_text_with_fallback(path)
    blocks = []
    for chunk in re.split(r"\n\s*\n", raw):
        chunk = chunk.strip()
        if chunk:
            blocks.append(Block("para", text=" ".join(chunk.split())))
    return blocks
```

### 2.2 md —— 天然友好

- `#` 系列 → heading（级别=井号数）；`| ... |` + 分隔行 → 表格；其余连续行 → 段落。
- 保留列表/表格/标题层级。

```python
m = re.match(r"^(#{1,6})\s+(.*)$", line)
if m:  blocks.append(Block("heading", text=m.group(2), level=len(m.group(1))))
# 表格：表头 + |---| 分隔行
if line.startswith("|") and re.match(r"^\s*\|[\s:\-|]+\|\s*$", lines[i+1]):
    table_rows = [_parse_md_row(line)]
    ...
    blocks.append(Block("table", rows=table_rows))
```

### 2.3 docx —— 结构化，但依赖作者用了"标题样式"

- 用 `iter_inner_content()` 按**真实顺序**遍历段落与表格（顺序很重要，否则表格/段落错位）。
- 标题靠 `paragraph.style.name` 判断（`Heading 1` → level 1）；正文取 `paragraph.text`；
  表格取 `Table` 的行列。
- 页眉/页脚在 `section.header/footer` 里，用 `iter_inner_content()` 天然排除。
- ⚠️ 若作者只是"加粗放大"而没用 Heading 样式，python-docx 判断不出标题——这是常见的结构流失。

```python
for item in d.iter_inner_content():
    if isinstance(item, Paragraph):
        style = (item.style.name or "").lower()
        m = re.match(r"heading\s*(\d)", style)
        blocks.append(Block("heading", text=item.text, level=int(m.group(1))) if m
                      else Block("para", text=item.text))
    elif isinstance(item, Table):
        blocks.append(Block("table", rows=[[c.text.strip() for c in r.cells] for r in item.rows]))
```

### 2.4 pdf —— 最难，且别指望一劳永逸

- **先分类**：文本型（有文字层）/ 扫描型（纯图，需 OCR）。扫描型本管线暂不含（后续可加 OCR）。
- **行级提取**：改用 `page.get_text("dict")` 逐行拿**字号/加粗**；行内拼接用「ASCII 词间补空格、CJK 直连」，避免中文跨行被 `split/join` 压出多余空格（如「这片 厚土」）。
- **标题启发式**：统计「按字符数加权的正文字号众数」作基准，字号 ≥1.35 倍 → level 1、≥1.15 倍或加粗短行 → level 2（`_heading_level`）；标题做**文档级去重**（防每页标题栏重复）；纯序号行（`01`/`1.`）直接丢弃。
- **段落合并（2026-08 修复「换行切段」）**：公告类 PDF 在 PyMuPDF 里常「一行=一个 text block」，旧逻辑会每行生成一个 para Block，把整句拆成多行。现按**行间距(y-gap)**合并：`_estimate_line_h` 估正文行高、`_merge_para_lines` 把 y 间距 ≤1.6×行高的相邻正文行并成**完整段落**；**标题/表格先判出并 flush 段落，绝不并入段落**（仅正文行之间按间距判断断句）。已知：编号列表项(1、2、3、)会被合进同一段；被拆两半的标题栏（如 `…来袭`+`袭`）不在本逻辑内。
- **表格**：`find_tables()` 检测，用 `_is_fake_table()` 判**真/假表格**（单行/单列判为误判，如实测公告里被误报成 1×1 的板块标题）；真表格保留 `table` 块并跳过其区域正文，**假表格区域短文本转 `heading` 候选**（不再当表格/正文）。
- **页眉/页脚（已放弃 2026-08）**：旧方案用**坐标边距启发式**剔除靠顶/底的块（`y0<60` 或 `y1>H-60`），已移除——本管线不考察页眉页脚；该机制会**误删文档标题**、又**漏掉文章元数据行**，改成正则又**过拟合到当前语料**，故整体放弃。只保留 cleaner 里领域无关的**页码/独立数字**噪音过滤。

```python
for page in doc:
    raw = page.get_text("dict")
    all_lines = [_line_info(ln, page.rect.height, header_margin, footer_margin)
                 for b in raw["blocks"] if b.get("type") == 0 for ln in b.get("lines", [])]
    body_size = _mode_body_size([i for i in all_lines if i])   # 正文字号加权众数
    # 1) 表格：真表保留，假表记录区域转标题候选
    for t in page.find_tables():
        rows = [[(c or "").strip() for c in r] for r in t.extract()]
        if _is_fake_table(rows): fake_rects.append(t.bbox)
        else: blocks.append(Block("table", rows=rows)); table_rects.append(t.bbox)
    # 2) 按序输出：标题/表格打断段落；正文行按 y 间距合并成完整段落
    line_h = _estimate_line_h(all_lines)
    body_buf = []
    def flush_para():
        nonlocal body_buf
        if body_buf:
            for para in _merge_para_lines(body_buf, line_h):
                blocks.append(Block("para", text=para))
            body_buf = []
    for b in raw["blocks"]:
        ls = [info for info in (_line_info(ln, page.rect.height, header_margin, footer_margin)
                                for ln in b.get("lines", [])) if info]
        if not ls: continue
        for info in ls:
            if _rect_in_any(info["bbox"], table_rects): flush_para(); continue
            if _rect_in_any(info["bbox"], fake_rects):   # 假表区域：被误判的板块标题
                level = 2 if len(info["text"]) <= 30 and info["text"][-1] not in "。！？；，,.;;" else 0
            else:
                level = _heading_level(info, body_size)
            if level:
                flush_para()
                key = (info["text"], level)
                if key not in seen_headings:
                    seen_headings.add(key)
                    blocks.append(Block("heading", text=info["text"], level=level))
            elif _PDF_ORDER_NO_RE.match(info["text"]): continue
            else: body_buf.append(info)
    flush_para()
```

### 2.5 xlsx —— 信息在表格结构里，不在文字里

- 按 **Sheet → 行列**读，识别"数据表格"：找到首行含 ≥2 个非空单元格、且下一行也满足的行作为表头，随后连续数据行为数据。
- 单格标题行（如"某型号技术参数"）单独作为 `para`。
- 日期/数字序列号、合并单元格重复值是常见坑（本项目样例未涉及）。

```python
grid = [[_clean_cell(c.value) for c in row] for row in ws.iter_rows()]
table = []
# 表格：非空单元格 >=2 且下一行也满足
if len([v for v in grid[i] if v]) >= 2 and len([v for v in grid[i+1] if v]) >= 2:
    ...收集连续行成 table → Block("table", rows=table)
elif len([v for v in grid[i] if v]) == 1:
    blocks.append(Block("para", text=grid[i][0]))   # 单格标题
```

### 2.6 pptx —— 每页信息密度低

- 按页遍历；标题取**标题占位符**（`slide.shapes.title`），正文取各形状文本，表格取 `has_table`。
- 每页标题按页序标成不同 `level`（页级标题）。
- ⚠️ 大量信息在图/图表里，纯文本抽取率低，常需 OCR 或人工补录。

## 3. 清洗（cleaner.py）

清洗**按块类型分别处理**，三道工序：**规范化 → 去噪 → 丢弃空块**。

### 3.1 规范化（normalize）

- **HTML 注释剔除**：`<!-- ... -->`（如 md 里的厂商备注）。
- **全角空格→半角**：`\u3000` → 半角空格。
- **连续空格→单个**：`[ \t]+` → 单个空格，再去首尾。
- **编码统一**：提取阶段已用回退策略保证中文不乱码。

```python
def _normalize_ws(text):
    text = HTML_COMMENT.sub(" ", text)      # 去 HTML 注释
    text = text.replace("\u3000", " ")      # 全角空格 -> 半角
    text = re.sub(r"[ \t]+", " ", text)     # 连续空格 -> 单个
    return text.strip()
```

### 3.2 去噪（denoise）

针对版式噪音，按规则剔除/匹配：

- **页脚/页码**：`第X页/共Y页`、单独的 `数字行`。（领域无关，保留）
- **页眉/页脚**：PDF 的坐标边距剔除已在 2026-08 放弃（不考察页眉页脚）；docx 用 `iter_inner_content()` 天然排除。
- 说明：规则只覆盖"常见"噪音；水印、logo 文字等需按真实文档补充规则。

```python
PAGE_NOISE = [r"第\s*\d+\s*页\s*/\s*共\s*\d+\s*页", r"第\s*\d+\s*页", r"^\s*\d+\s*$"]
def _is_noise(text):
    return any(re.search(p, text) for p in PAGE_NOISE)
```

### 3.3 丢弃空块

- 标题/段落：规范化后为空或命中噪音 → 丢弃。
- 表格：删掉全空行；整个表空 → 丢弃。

```python
def clean_block(block):
    if block.kind in ("heading", "para"):
        text = _normalize_ws(block.text)
        if not text or _is_noise(text): return None
        return Block(block.kind, text=text, level=block.level)
    if block.kind == "table":
        rows = [[_normalize_ws(c) for c in r] for r in block.rows]
        rows = [r for r in rows if any(c for c in r)]
        return Block("table", rows=rows) if rows else None
```

## 4. 产物与清单（pipeline.py）

对每份文档同时产出：
- **`*.jsonl`**——结构化语料（每行一个 Block），切片器直接读，免重复解析。
- **`*.md`**——渲染后的文本，供人核对。
- **`manifest.jsonl`**——记录来源/格式/语料路径/块数/字符数，便于溯源与验收。

```python
def write_blocks_jsonl(blocks, out_path):
    with open(out_path, "w", encoding="utf-8") as f:
        for b in blocks:
            f.write(json.dumps(dataclasses.asdict(b), ensure_ascii=False) + "\n")
```

## 6. 已知限制与后续

- **去重**：本版本未做。后续第二版做"完全一致才删 + 高度相似只标记"；阈值等真实数据定。
- **txt/md 的列表**：被压平成一行（如 `- a - b`）。txt 无结构、md 列表重解析有损，是已知薄弱点。
- **PDF 标题/表格**：依赖字号/加粗启发式 + `_is_fake_table()` 真伪判别，能识别带字号梯度的公告类标题与误判表格；但启发式对「无字号梯度 / 复杂分栏 / 底色标题」仍可能漏判；扫描型 PDF 需加 OCR。
- **图片/公式**：本版本未抽取（图片里的字、公式需 OCR 或多模态）。真实文档有图时需补。

---

## 7. 一句话总结

> 数据准备 = **提取（把各格式统一成 Block 的头/正文/表）→ 清洗（规范化 + 去噪 + 丢弃空块）→
> 落盘结构化语料（jsonl）+ 人核对文档（md）**。核心在于用 `kind` 语义标签承载结构，
> 让接下来的"切片"能按标题边界切、把表格当整体、不丢失语义边界。

## 附录：本项目疑问 · 解答与生产环境对比

> 记录我在数据准备阶段提出过的疑问、本项目的解决思路，以及它与"真实生产环境"做法的对比。
> 相似/递进的问题归并在同一组。

### 疑问组一：中间表示 / 统一格式，是真实的吗、是必要的吗？（递进三问）

**Q1. 能否先把 Word/PDF 统一转成 Markdown 再处理？**
- **本项目**：可行，但**不作为主方案**。原因：①转换工具内部同样要先解析原文档，躲不开原本的难题（garbage in, garbage out）；②表格/排版在转 md 时会丢或拉平，而表格恰是"事实型问题"的答案所在；③转 md 有损、不可逆。**采用"原生格式直接解析 + Block 保结构"**。
- **生产环境**：同样是**直接解析原生结构**，从不以 md 作解析通道。复杂文档用 **Unstructured / Docling / Azure Document Intelligence / AWS Textract**，返回**带类型的元素**（`Title` / `Table` / `NarrativeText` / `ListItem`…）。md 在这些工具里只是展示/中间文本。

**Q2. "统一中间格式"是必须步骤吗？真实项目有这一步吗？**
- **本项目**：**不是硬性步骤**，但作为"工程化产出"价值在于可审计、可复用、免重复解析。落成 `jsonl` 语料 + `md` 核对。
- **生产环境**：**不一定有**。简单 RAG（LangChain 系）直接 Loader → `Document(page_content + metadata)` → 切片，**没有单独的"中间格式"步骤**；只有复杂/规模化的 RAG 才做"语料层"（把 chunk/Node 存进 doc store 或关系表）。所以我们这套属**推荐而非必须**。

**Q3. 结构化块 Block 是真实 RAG 的常用方案吗？**
- **本项目**：`Block(kind=heading/para/table)` 是我们的**简化自制版**。
- **生产环境**：**"类型化块"这个思路是真实且进阶的**，全球对应物就是 Unstructured 的 `Element`、Textract/Azure 的 typed blocks、Docling 的结构化文档。分两种流派：
  - **A 文本切分**（框架 Document + 按 token/标题切）——最普遍、教程都是它；
  - **B 布局/结构感知**（带类型元素再按结构切）——文档越乱越要用，正是我们这套。
  - 本项目偏 **B**，对文档质量要求高的真实 RAG 更稳。**差异点**：接框架时需把 Block 转成框架的 `Document/Node`；持久化通常进 doc store / 向量库而非 jsonl（我们 jsonl 便于学习与核对）。

### 疑问组二：清洗 / 去重等"预处理流程"，与重复文件处理

**Q4. 除了提取，清洗、去重等其他预处理流程呢？两份重复/高度相似的文件怎么处理？**
- **本项目**分层：**提取 ≠ 清洗 ≠ 去重 ≠ 规范化**（不同阶段）。
  - 规范化：编码统一、全角转半角、空白压缩；清洗：去页眉页脚、页码、HTML 注释、空行。
  - 去重：第一版**只做安全去重**——规范化后**完全一致才删**，**高度相似只标记不删**（零误删风险）；**阈值推迟到真实数据**，基于相似度分布再定。
- **生产环境**：去重**分层**（文件级 / 内容级 / 片段级）且**方法由粗到细**：哈希（精确）→ **SimHash / MinHash+LSH**（近似，适于海量）→ **embedding**（语义）。关键原则 **相似 ≠ 重复**（版本差异、同主题不同文档、相似但关键信息不同都不能乱删），所以生产上多"**先标记候选，再按规则处理**"而非"相似就删"。大规模语料还有**版本覆盖策略**（新版本覆盖旧版，避免新旧打架）。我们第一版推迟这些，正是等真实数据。

### 疑问组三：页眉/页脚"坐标边距启发式"（怎么解释 + 生产对比）

**Q5. 页眉/页脚用"坐标边距启发式"剔除靠顶/底的块，怎么解释？**
- **⚠️ 2026-08 已放弃该方法**：原假设"页眉贴顶、页脚贴底"，把离顶/底 60pt 内的块当页眉页脚丢弃。实测对这批公告类 PDF **会误删文档标题**（标题 y≈42<60 被删）、又**漏掉文章元数据行**（元数据 y≈90>60 没删）。且改成正则又**过拟合到当前语料**。故本管线**不考察页眉页脚**，整体放弃该启发式，只保留 cleaner 里领域无关的页码/独立数字过滤。
- **生产环境**：真实生产**不手写这层**，而是交给 **Docling / Unstructured / Azure / Textract 的布局分析**自动识别页眉页脚、栏数、首行缩进等，效果更好；但**本质仍是启发式、非百分百**，复杂版式仍需人工。我们实现的"坐标边距 + 正则"就是它们的**简化版**——思路一致、性价比高。

### 总结对比表

| 维度 | 本项目 | 真实生产环境 |
|---|---|---|
| 解析介质 | 原生格式直接解析，md 仅作核对 | 同；复杂文档用 Unstructured/Docling/Textract |
