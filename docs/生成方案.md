# 生成方案

> 管线第 ⑤ 步：基于检索到的片段生成**带引用**的回答，并在检索置信度不足时**拒答**。
> 指标结果见 `验收复盘_混合重排.md`；检索与分数语义见 `检索方案.md`。

## 1. 定位

| 项 | 内容 |
|---|---|
| 输入 | 用户问题 + `检索方案` 产出的 top-k 命中（含分数与溯源坐标） |
| 输出 | 带 `[chunk_xxxxxx]` 引用的自然语言回答；或拒答文案（不调用生成模型） |
| 代码 | `scripts/run_rag.py`（端到端 + 提示词 + 调用封装）、`scripts/gen_answers.py`（批量）、`scripts/eval_generation.py`（生成侧评测） |

## 2. 流程

```
问题 ──► ① 前置检查（.env / 向量库 / 切片产物）
          │
          ▼ ② 检索 top-k（路线由 --mode 决定，默认 hybrid_rerank）
          │
          ▼ ③ 阈值拒答判定：top-1 分数 < 该路线阈值？
          │        ├─ 是 → 输出 REJECT_ANSWER，**不调用生成模型**
          │        └─ 否 ↓
          ▼ ④ 拼上下文：以 chunk id 为编号 + 来源附录（doc §section 页码）
          │
          ▼ ⑤ 组装 messages：规则放 system，资料 + 问题放 user
          │
          ▼ ⑥ 调用 qwen-flash（带重试）
          │
          ▼ ⑦ 引用机械校验：回答里的 chunk id 是否都来自本次资料
```

> **生成顺序（重要）**：拒答阈值必须**在生成之前定稿**——生成要用它决定是否拒答。
> 顺序是：检索 pass 落快照 → 离线标定阈值 → 人工确认 → 回填 `MIN_SCORE_DEFAULT` → 再跑批量生成。

## 3. 关键设计

### 3.1 提示词结构：规则集中在 system

```
system : SYSTEM_PROMPT（三条规则：只用资料、资料不足必须拒答、按编号标注引用）
user   : 【资料】…（各片段，以 chunk id 编号）
         【问题】…
```

规则只在一个常量里定义，`run_rag`（交互式）与 `gen_answers`（批量）**共用同一个组装函数**
`build_messages()`；user 消息**只承载数据与任务**，不重复规则。这样改规则只需改一处，
也避免同一约束出现两种措辞。

规则 2 的当前措辞（本轮加强，配合纯向量路线阈值较宽松的做法）：

> 若【资料】不足以回答问题——完全没有相关内容，或只提到一部分、缺少回答所需的关键信息——
> **必须直接回答「资料中没有相关信息」**，不要猜测、不要编造、也不要用常识补全。

### 3.2 引用用 chunk id，而非位置编号

上下文片段以 `[chunk_000023]` 形式编号，并要求模型按同样格式标注引用。

原因：位置编号（`[1]`、`[2]`）只在**本次检索结果内**有效——换问题、换路线、换库即指向别的片段，
回答文本本身不自包含。chunk id 是**全局唯一**标识，脱离本次检索也能定位。

配套**机械校验** `extract_citations()`：解析回答中的 `[chunk_xxxxxx]`，与本次资料比对，得到
「有效引用 / 无效引用（越界或编造编号）/ 未标注引用」三类结果；交互式运行时打印，批量生成时落盘。
LLM 判分未必能发现编号越界，这一步是硬校验。

### 3.3 阈值拒答（分路线）

拒答判定只看 **top-1 分数**与**该路线阈值**：

| 路线 | score 语义 | 阈值 |
|---|---|---|
| `vector_only` | 余弦相似度 | **0.55** |
| `hybrid_rerank` | 重排 relevance 分 | **0.58** |

两条路线的分数尺度不同，**必须各配一个阈值**，不能共用一个数。
阈值由 `scripts/calibrate_threshold.py` **离线读检索快照**标定：给出正类（可答）/负类（不可答）的 top-1 分布、
可分离区间与「正类误杀 vs 负类漏拦」的**阈值区间权衡表**，人工确认后回填 `run_rag.MIN_SCORE_DEFAULT`
与 `metrics.json.threshold`；标定细节见 `验收复盘_混合重排.md`。

拒答时输出固定文案 `REJECT_ANSWER = "当前资料相关性不足，无法回答"`，**不调用生成 API**。
纯向量路线 0.55 会漏拦部分不可答题（本轮 6 道拦下 2 道），这些题交给生成模型自保——因此提示词里
"资料不足必须拒答"这条规则是**配套约束**，不是可选修饰。

### 3.4 两类拒答的区分

| 情形 | 触发层 | 措辞 | 含义 |
|---|---|---|---|
| **阈值拒答** | 系统（阈值） | 当前资料相关性不足，无法回答 | 检索没找到相关内容（压根未调用生成） |
| **模型级拒答** | 生成模型 | 资料中没有相关信息 | 找到了资料，但资料里没有提到该问题 |

两者刻意用不同措辞：前者说明「库里没有」，后者说明「库里相关但未覆盖这一点」。

### 3.5 调用重试与失败标记

`chat()` 对网络类错误（超时、连接错误）与 HTTP 429/5xx 做**指数退避重试**（共 4 次尝试，退避 2/4/8 秒）；
4xx（除 429）属请求本身问题，不重试。

批量生成时，若重试后仍失败，`gen_answers` 会**保留已检索到的结果**并写入 `error` 字段，
**不伪装成「阈值拒答」**；生成侧评测跳过这类记录并单独报数。这样"基础设施故障"与"模型行为"
在产物里可区分，不会把前者当作 0 分计入指标。

## 4. 参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 生成模型 | `qwen-flash` | 可 `--model` 覆盖（见 `run_rag.DEFAULT_CHAT_MODEL`） |
| 判分模型 | `qwen3.7-flash` | **与生成模型分开配置**（`eval_generation.DEFAULT_JUDGE_MODEL`），减少同模型自评偏差 |
| 接口 | `POST /compatible-mode/v1/chat/completions` | OpenAI 兼容 |
| `max_tokens` | 1024 | |
| `temperature` | 0.3 | 生成；判分时用 0.0 |
| `timeout` | 90 秒 | 单次请求 |
| 重试 | 3 次（共 4 次尝试） | 退避基数 2 秒 |
| 默认路线 | `hybrid_rerank` | 见 `run_rag.DEFAULT_MODE` |
| 默认 top-k | 5 | 覆盖多来源题的上限；批量按集取 `QA_K`（**两集统一 5**） |
| 拒答阈值 | 0.55 / 0.58 | 按路线，见 `MIN_SCORE_DEFAULT`（离线标定后回填） |

## 5. 代码结构

```
scripts/
├─ run_rag.py         # SYSTEM_PROMPT / build_context / build_messages / extract_citations
│                     #   chat（重试）/ MIN_SCORE_DEFAULT / REJECT_ANSWER / preflight
├─ gen_answers.py     # 批量生成：按集取 k、阈值拒答、失败标 error
└─ eval_generation.py # 生成侧评测：LLM-as-judge 四维度
```

```powershell
# 交互式（默认混合+重排，阈值取 0.58）
.venv_rag311\Scripts\python.exe -m scripts.run_rag "「逐猎狂途」是几人制的娱乐竞技玩法？"

# 批量生成（评测用；文件名一律用全名 route）
.venv_rag311\Scripts\python.exe scripts\gen_answers.py --mode hybrid_rerank --sets all --out data\eval\answers_hybrid_rerank.jsonl

# 生成侧评测（LLM-as-judge，默认判分模型 qwen3.7-flash；--answers 缺省即 answers_{mode}.jsonl）
.venv_rag311\Scripts\python.exe scripts\eval_generation.py --mode hybrid_rerank --out data\eval\gen_scores_hybrid_rerank.jsonl
```

## 6. 生成侧指标口径（定义，不列结果）

`eval_generation.py` 采用 **LLM-as-judge**：由 `qwen3.7-flash` 对每条回答按四个维度打分（0 / 0.5 / 1，
`temperature = 0.0`），输入为「问题 + 标准答案 + 是否可答 + 检索资料 + 系统回答」。

| 维度 | 判什么 |
|---|---|
| 忠实度 | 回答是否忠于检索资料、有无编造 |
| 引用准确率 | `[chunk_xxxxxx]` 标注是否指向能支撑对应句子的片段 |
| 答案正确率 | 与标准答案是否语义一致（不可答题：表达了拒答即得 1，编造得 0） |
| 拒答正确性 | 不可答题是否拒答；可答题是否未误拒 |

代码只负责组装判分提示、解析模型返回的 JSON、并对各维度求算术平均。
**平均范围是全部 60 题**（含不可答题）——与检索侧只在 54 道可答题上算**口径不对称**，两侧不可互相换算。

## 7. 已知限制

- **生成侧指标与提示词/判分模型版本绑定**：提示词结构、引用格式或判分模型一变，「系统」即发生变化，
  历史指标不可直接比较。
- **LLM-as-judge 的偏差**：判分模型与生成模型虽已分开配置，仍是同一家模型族，存在评分偏好；
  且 0 / 0.5 / 1 属**有序等级**，直接求算术平均隐含「按等距数值处理」的简化。
- **多跳问题证据不足**：单轮 top-k 检索对需整合 1~4 篇来源的问题覆盖不全，导致这类题答案正确率偏低
  （瓶颈在检索而非生成忠实度：complex 忠实度 0.833，答案正确率仅 0.667）。
- **`timeout=90s` 对长上下文偏紧**：重试可覆盖多数瞬态抖动，但极端慢响应仍会失败（失败会被显式标记，不计入指标）。
